## 三、从拆解表导出的关键发现

### 1. 竞品"标配"能力（不做就缺位，必须纳入 MVP 基线）
- 多轮对话问数、实时查询、下钻联动、元数据接入、行列级权限——**几乎全员具备**，是入场门槛而非差异点。
- 自然语言→可视化（描述出图）：PBI、Tableau 已做深，是"可视化优先"品类的显性能力。

### 2. 竞品"薄弱 / 普遍缺失"的能力（= 差异化空白，新产品机会）

| 空白点 | 现状 | 为什么对分析师重要 |
|--------|------|--------------------|
| **SQL 可编辑 / 人在回路批准** | 仅 Vanna 做到强；其余均 △（能看到但难改/难控） | 分析师要"审阅再执行"，黑盒生成不可信 |
| **执行溯源 / 工作台完整日志** | 普遍 △，仅开源 ChatBI / Vanna 验证"完整日志"受欢迎 | 可审计 = 可进入正式工作流的前提 |
| **结果沉淀为可复用语义资产** | 仅 Aloudata / 衡石 明确；其余 △ | 每次问答都从零生成 = 重复劳动，资产不积累 |
| **跨源中立 + 私有化** | 云厂商（Genie/Cortex/小Q）绑定自家；独立派（Fine/衡石/火山/Vanna）才中立 | 分析师常跨多个数仓/数据库，且金融/政企要私有化 |
| **自动学习更新元数据（feedback agent）** | 多数 ?，开源 ChatBI 已验证此思路 | 语义层越用越准，是冷启动后的护城河 |

### 3. 路线分野（决定产品基因）

| 路线 | 代表 | 对分析师的友好度 |
|------|------|------------------|
| NL2SQL 直出（无语义层） | FineChatBI、小Q | 低——口径漂移、不可审计 |
| 语义模型引导 Text2SQL | Genie、Cortex | 中高——准且可治理，但 SQL 仍偏黑盒 |
| 指标/语义层 Text2Metrics | 衡石、Aloudata | 高可信——但建模重、灵活度受限 |
| 开源 RAG2SQL + 完全可控 | Vanna | **最高可控**——但需工程师自建，无开箱治理 |

## 四、MVP 功能取舍建议（基于上表）

**P0（必须做，否则不入流）**
- 多轮对话问数 + 实时查询 + 下钻联动
- 元数据 / 表字段 / 业务术语轻量接入
- 生成 SQL **可见 + 可编辑 + 人在回路批准执行**
- 执行溯源日志（工作台）
- 行列级权限

**P1（差异化，拉开与"业务人员型 ChatBI"的距离）**
- SQL 导出到 Notebook / SQL 客户端
- 结果沉淀为可复用指标 / 语义资产
- 跨多数据源中立接入 + 私有化部署
- feedback agent：问答后自动学习更新元数据

**P2（价值高地，后期建立壁垒）**
- 智能归因 / 异常预警 / 自动报告
- 自动仪表盘生成
- Agent 化：定时任务、Skills 接入、端到端分析闭环

**明确不做 / 延后**
- 纯 NL2SQL 直出（无语义层校验）——规避"CheatBI"信任陷阱
- 过度依赖可视化炫技（先让分析师"查得准、改得了"，再谈"出图好看"）
