# ChatBI 产品需求文档（PRD）—— 功能清单与验收标准

> 文档类型：PRD · 功能清单（带验收标准）
> 产品定位：**数据分析师 / 工程师的 AI 副驾（Copilot for Analytics）**
> 版本：v1.0 · 编制：2026-08
> 配套文档：① 市场与竞品分析 ② 竞品功能点逐项拆解表 ③ 分析师用户访谈提纲
> 优先级约定：**P0=必须（MVP 基线）｜P1=差异化（拉开差距）｜P2=价值高地（后期壁垒）**

## 一、PRD 概要

### 1.1 背景与目标
ChatBI 主流方案多为"业务人员自助"设计，存在幻觉、口径漂移、不可审计三害。**本产品面向分析师/工程师，定位"副驾"**：不替分析师做主，只让其更快——每一句 SQL 都看得见、改得了、存得下。

### 1.2 目标用户
- 主：数据分析师、数据工程师（每周 ≥3 天写 SQL / 取数）
- 覆盖：中台分析师（服务多业务线）、独立数据工程师（小团队唯一 data 角色）、业务侧分析师（会用 SQL 但不深）

### 1.3 成功指标（北极星 + 验收口径）
| 指标 | 定义 | 目标（MVP 后 3 个月） |
|------|------|------------------------|
| **取数任务端到端耗时** | 从提问到可用结果 | 较现状下降 ≥ 40% |
| **SQL 采纳率** | 生成 SQL 被批准执行的比例 | ≥ 80% |
| **一次可执率** | 生成 SQL 无需改写即可跑通 | ≥ 60%（P0 达标线） |
| **资产复用次数** | 已沉淀查询/指标被再次调用 | 周人均 ≥ 3 次 |
| **分析师周活留存** | 连续 4 周使用 | ≥ 60% |

### 1.4 范围（In / Out）
- **In**：自然语言问数、可控 SQL（可见/可改/批准）、执行溯源、语义层轻量治理、跨源接入、私有化、基础可视化与下钻。
- **Out（本期不做）**：纯 NL2SQL 无语义校验直出、过度可视化炫技、面向业务人员的"全员自助"营销叙事、预测建模引擎。

## 三、功能详细定义与验收标准

### M1 自然语言交互与取数

**F-101 多轮对话问数（P0）**
- 描述：支持基于上下文的连续追问与澄清，理解指代（"它""上个月""同比"）。
- 验收标准：
  - AC1 用户第二问含指代代词时，系统能正确绑定上一轮实体并执行。
  - AC2 上下文窗口至少保留最近 5 轮，刷新或新会话后可手动清除。
  - AC3 切换数据集/指标时，系统提示上下文已变更。

**F-102 业务术语理解（P0）**
- 描述：将口语/同义词映射到已定义的字段与口径（如"成交额"→`gmv`）。
- 验收标准：
  - AC1 在已配置术语表的前提下，对同义词提问命中正确字段，准确率 ≥ 90%（测评集）。
  - AC2 未命中时进入澄清流程而非强行猜测（见 F-104）。

**F-103 实时查询执行（P0）**
- 描述：生成的 SQL 在目标数据源实时执行并返回结果。
- 验收标准：
  - AC1 在标准数仓上，亚秒级~分钟级查询返回结果与直连客户端一致。
  - AC2 执行超时/报错时给出可读错误与定位建议。

**F-104 模糊问数智能澄清（P1）**
- 描述：提问歧义或信息不足时主动反问，而非生成"看似合理"的错误 SQL。
- 验收标准：
  - AC1 当提问存在 ≥2 种合理解读时，系统列出选项让用户选择，不直接执行。
  - AC2 澄清后生成的 SQL 与所选口径一致。

**F-105 多数据集/跨表查询（P1）**
- 描述：支持跨多个数据源/表的关联查询。
- 验收标准：
  - AC1 在已配置 join 关系下，跨表查询生成的 SQL 包含正确关联条件。
  - AC2 未配置关联时，提示用户补充关系而非编造。

### M2 语义层与治理

**F-201 元数据接入（P0）**
- 描述：轻量接入库/表/字段/注释/枚举值/样例 SQL。
- 验收标准：
  - AC1 支持从数据源自动拉取表结构并允许人工补充注释。
  - AC2 接入后术语理解（F-102）准确率较未接入提升 ≥ 20%。

**F-202 业务术语/枚举值管理（P0）**
- 描述：可配置同义词、口径说明、枚举值业务含义。
- 验收标准：
  - AC1 提供术语管理界面，支持增删改与版本记录。
  - AC2 枚举值（如 status=1 表示"已支付"）在生成 SQL 时被正确翻译。

**F-203 指标语义层/统一口径（P1）**
- 描述：定义指标及其计算逻辑，作为唯一事实源，避免口径漂移。
- 验收标准：
  - AC1 指标定义后可被自然语言直接引用，生成 SQL 严格遵循定义。
  - AC2 同一指标在不同提问下计算结果一致（口径统一）。

**F-204 feedback agent 自动学习元数据（P1）**
- 描述：用户纠正一次（改 SQL/选口径）后，系统更新语义资产，越用越准。
- 验收标准：
  - AC1 用户改写 SQL 并标记"保存为正确口径"后，后续同类提问命中修正。
  - AC2 学习记录可审计、可回滚。

**F-205 数据血缘/权限继承（P0，依赖 F-503）**
- 描述：问数权限继承底层数据源行列级权限。
- 验收标准：
  - AC1 无权限的表/字段不出现在可问范围，且不泄露于任何返回。

### M3 SQL 可控性 / 可审计（核心差异 ★）

**F-301 生成 SQL 可见（P0）★**
- 描述：展示完整、格式化、带注释的生成 SQL，非黑盒。
- 验收标准：
  - AC1 每次问数后默认展示完整 SQL（非折叠摘要）。
  - AC2 关键过滤/聚合逻辑处有权威注释指向所用术语/指标定义。

**F-302 SQL 可编辑/改写（P0）★**
- 描述：用户可在执行前直接编辑 SQL 草稿。
- 验收标准：
  - AC1 提供可编辑 SQL 编辑器（高亮/补全），改动后可重新校验。
  - AC2 编辑后执行以"用户最终版本"为准，并记录"原始生成版 vs 最终版"差异。

**F-303 人在回路批准执行（P0）★**
- 描述：SQL 须用户确认后才执行，杜绝自动跑数。
- 验收标准：
  - AC1 默认不自动执行；点"运行"后才提交。
  - AC2 涉及写操作（INSERT/UPDATE/DDL）强制二次确认或禁用。

**F-304 执行溯源/工作台日志（P0）★**
- 描述：完整记录"提问→生成→改写→批准→执行→结果"全链路。
- 验收标准：
  - AC1 每条记录含时间、用户、自然语言、SQL 各版本、数据源、耗时、结果摘要。
  - AC2 可一键回放任一历史问答并复现。

**F-305 导出到 Notebook/SQL 客户端（P1）**
- 描述：一键导出最终 SQL 到主流环境。
- 验收标准：
  - AC1 支持复制为纯 SQL、导出为 .sql、对接 Jupyter/Databricks Notebook。
  - AC2 导出保留注释与口径说明。

**F-306 结果沉淀为可复用资产（P1）**
- 描述：将问答保存为查询/指标/看板，团队可复用。
- 验收标准：
  - AC1 可命名保存，支持搜索与权限共享。
  - AC2 复用时不重新从零生成，直接调用已校验逻辑。

### M4 分析洞察与可视化

**F-401 下钻/切片/联动（P0）**
- 描述：结果集支持维度下钻、筛选、图表联动。
- 验收标准：
  - AC1 点击维度值可下钻，生成对应下钻 SQL 并走 F-303 批准。
  - AC2 图表与表格联动一致。

**F-402 自然语言→可视化（P1）**
- 描述：描述"想看什么"自动选图并生成。
- 验收标准：
  - AC1 对常见图表诉求（趋势/占比/对比）自动选型合理率 ≥ 80%（人工评）。
  - AC2 生成图表可编辑类型与字段。

**F-403 智能归因（P2）**
- 描述：指标波动自动拆解维度归因。
- 验收标准：
  - AC1 给定指标异常，输出 Top-N 贡献维度及量化影响。
  - AC2 归因逻辑可解释、可溯源到原始 SQL。

**F-404 异常预警（P2）**
- 描述：指标越界自动提醒。
- 验收标准：
  - AC1 可配置阈值/同环比规则，触发后推送。
  - AC2 预警附带"一键下钻归因"入口。

**F-405 自动报告生成（P2）**
- 描述：将问答/归因组织成自然语言报告。
- 验收标准：
  - AC1 报告含结论、数据、图表，且结论可被溯源。
  - AC2 支持定时生成与导出。

### M5 数据源 / 部署 / 安全

**F-501 多数据源接入（跨源中立）（P0）**
- 描述：支持主流数仓/数据库，不绑定单一厂商。
- 验收标准：
  - AC1 MVP 至少支持 Postgres / MySQL / Hive / ClickHouse 中 3 类。
  - AC2 新增数据源配置 ≤ 10 分钟（含权限）。

**F-502 私有化/自托管部署（P1）**
- 描述：支持 VPC/本地部署，数据不出域。
- 验收标准：
  - AC1 提供容器化部署包，离线环境可起。
  - AC2 推理可走私有/自建模型，不强制公网 LLM。

**F-503 行列级权限（P0）**
- 描述：对接数据源权限，行/列级隔离。
- 验收标准：
  - AC1 用户仅能问到被授权范围的字段与行。
  - AC2 越权提问返回"无权限"且不泄露结构。

**F-504 信创适配（P2）**
- 描述：兼容国产库/芯片/OS。
- 验收标准：
  - AC1 在指定信创栈（如鲲鹏+麒麟+国产库）可运行核心链路。

**F-505 开放 API / 嵌入（P1）**
- 描述：问数能力以 API/组件形式嵌入其他系统。
- 验收标准：
  - AC1 提供问数 API（鉴权/限流/日志）。
  - AC2 可嵌入 iframe/SDK 到内部分析平台。

### M6 Agent 化 / 自动化（P2）

**F-601 定时任务（P2）**：可定时跑问数/报告并推送。AC：可配置 cron，失败重试与告警。
**F-602 Skills / 工具接入（P2）**：扩展外部工具（爬虫/API/算子）。AC：插件机制，沙箱执行。
**F-603 端到端分析闭环（P2）**：从问数到归因到行动建议。AC：多步 Agent 可暂停人工确认。

## 四、MVP 范围与里程碑

- 交互：F-101/102/103 · 语义：F-201/202/205 · **SQL 可控：F-301/302/303/304（★核心）** · 洞察：F-401 · 部署：F-501/503

## 五、依赖、风险与开放问题

**依赖**
- LLM/微调能力（可控 SQL 生成质量依赖基座模型 + 语义层引导）。
- 数据源连接器的稳定性与权限接口。

**风险**
- R1 一次可执率不达标 → 缓解：语义层引导 + 人在回路兜底（F-303）。
- R2 私有化推理资源成本 → 缓解：支持小模型/量化部署。
- R3 语义冷启动慢 → 缓解：feedback agent（F-204）+ 元数据自动拉取（F-201）。

**开放问题（待访谈/实测确认，见访谈提纲 H1–H6）**
- 分析师对"自动学习元数据"的信任边界在哪？（H6）
- 跨源 join 的语义关系谁来配、配多细？（F-105/F-203）
- 付费模式：按席位 / 按量 / 买断？（访谈 G2）
