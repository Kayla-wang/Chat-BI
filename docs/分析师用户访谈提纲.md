## 一、研究目标与待验证假设

本次访谈不为"推销产品"，而是**用真实行为验证假设**。基于竞品拆解，我们提出以下待验证命题（访谈后要逐条标记：验证 / 推翻 / 需补充）：

| 编号 | 假设（Hypothesis） | 来源 |
|------|-------------------|------|
| H1 | 分析师对"黑盒生成的 SQL"普遍不信任，需要**可见、可改、可批准** | 拆解表 C 域：仅 Vanna 强可控 |
| H2 | 现有 ChatBI "能看到 SQL 但难改、缺完整执行日志"，是高频痛点 | 拆解表 C 域普遍 △ |
| H3 | 分析师的问答结果**未被沉淀**，每次从零生成造成重复劳动 | 拆解表 B/C：仅 Aloudata/衡石明确沉淀 |
| H4 | 分析师常需**跨多个数仓/数据库**取数，且金融/政企场景要求私有化 | 拆解表 E：云厂商绑定自家 |
| H5 | 分析师更想要"副驾（Copilot）"而非"替代者"，即先准后快 | 市场分析结论 |
| H6 | "自动学习更新元数据（feedback）"是冷启动后可感知的价值点 | 拆解表 B：多数 ? |

## 二、受访者筛选标准

**硬性门槛（需全部满足）**
- 当前岗位为数据分析师 / 数据工程师 / 算法工程师(偏数据)，且**每周至少 3 天写 SQL 或做取数分析**。
- 所在团队使用至少 1 种 BI 工具 + 1 种 SQL/Notebook 环境。
- 近 3 个月有过"为业务方取数"或"自助分析"经历。

**配额建议（每轮 8–12 人）**
| 维度 | 分层 | 目标人数 |
|------|------|----------|
| 角色 | 数据分析师 / 数据工程师 | 各 50% |
| 行业 | 互联网 / 金融 / 零售消费 / 其他 | 均衡覆盖 |
| 规模 | 大厂数据中台 / 中小团队 | 均衡 |
| 现有工具 | 用过 ChatBI 类工具 / 纯传统方式 | 两类都要有 |

**排除**：纯业务方、纯前端/后端开发（无取数职责）、竞品厂商在职员工。

## 三、3 个典型 Persona（用于招募与对照）

1. **「中台分析师」Ada**：大厂数据中台，服务多个业务线，每天被"临时取数"打断，精通 SQL，厌恶重复劳动。
2. **「独立数据工程师」Ben**：中小团队唯一 data 角色，既要建模又要取数，对私有化/信创敏感，工程能力强。
3. **「业务侧分析师」Cara**：贴近业务的分析师，会用 SQL 但不深，既想要自助又怕查错背锅。

## 五、访谈脚本（开放性问题为主，避免引导）

### 暖场
- 感谢参与，说明"没有正确错误答案，我们想听真实吐槽"。
- 确认：你当前主要用哪些工具取数/分析？（SQL 客户端、Notebook、BI、其他）

### 模块 A：日常工作流（行为回顾）
- A1. 描述你**昨天/上周**一次典型的取数或分析任务，从接到需求到交付，经历了哪些步骤？
- A2. 你**最常用的取数入口**是什么？为什么是它而不是别的？
- A3. 你写 SQL 时，有没有"模板/片段/常用查询"可以复用？怎么管理的？

### 模块 B：痛点与低效（找痛点场景）
- B1. 回想最近一次**因为取数卡住/返工**的经历——卡在哪？最后怎么解决的？
- B2. 当业务方问"上周华南区 GMV 是多少"，你第一反应是开心还是头疼？为什么？
- B3. 你觉得现在流程里**最浪费时间**的三件事是什么？（让对方排序）

### 模块 C：对"自然语言对话取数"的态度（H5）
- C1. 你用过 ChatBI / 自然语言问数类工具吗？**第一次用的真实感受**是什么？
- C2. 如果系统直接给你一个"答案/图表"，你**敢直接信、直接发给老板**吗？什么情况下不敢？
- C3. 你理想中"AI 帮你取数"应该**先快还是先准**？举个例子说明。

### 模块 D：SQL 可控性 / 可审计（★ 核心，验证 H1/H2）
- D1. 当 AI 生成了一段 SQL，你希望看到它吗？希望**能改它**吗？为什么？
- D2. 你现在会**审阅**别人/上游给的 SQL 吗？还是直接跑？什么决定了你的信任？
- D3. **关键问题(KQ)**：如果工具生成了 SQL 但你**改不了、也看不到完整执行过程**，你还会用吗？什么场景会用、什么场景绝对不用？
- D4. 你交付分析时，有没有被问过"这个数字**怎么算出来的**"？你当时怎么回答的？你希望工具帮你留痕吗？
- D5. 如果工具能生成一条带注释、可一键导进你 Notebook 的 SQL，对你价值大吗？

### 模块 E：语义层 / 知识沉淀（验证 H3/H6）
- E1. 你们团队对"GMV/活跃用户/销量"这类指标，**口径统一**吗？不统一时怎么扯皮？
- E2. 你过去写过的取数逻辑，**下次还会重新写一遍**吗？还是有人/系统帮你记着？
- E3. **关键问题(KQ)**：如果系统能"越用越懂你们业务口径"（你纠正一次它就记住），这会不会让你更愿意用？还是你担心它记错？
- E4. 你们团队有"指标字典/数据资产"这类东西吗？谁维护？维护成本高吗？

### 模块 F：部署 / 安全 / 跨源 / 采购（验证 H4）
- F1. 你们的数据放在几个地方？（数仓/数据库/湖）取数时要**跨好几个源**吗？
- F2. 公司/行业对数据**私有化、权限、信创**有硬性要求吗？影响了你们选工具吗？
- F3. 如果引入这类工具，谁拍板？最在意的**前三顾虑**是什么？（安全/准确率/成本/上手）

### 模块 G：场景优先级 & 付费意愿
- G1. 下面这些能力，按"没有就完全不会用 → 有就加分"排个序：
  - 自然语言问数 / 多轮对话
  - 生成 SQL 可改可批准
  - 完整执行日志与溯源
  - 结果沉淀为可复用指标
  - 归因分析 / 异常预警
  - 自动报告 / 仪表盘
  - 私有化部署
- G2. 如果真有"可控、可审计、跨源"的分析师副驾，你/团队**愿意怎么付费**？（按席位/按量/买断/不愿意）
- G3. 你现在为"取数效率"付出的隐性成本（等排期、反复沟通）大概值多少？

### 模块 H（可选）：原型/概念演示反馈
- 展示 1–2 个核心流程（自然语言→SQL草稿→审阅改写→执行→日志）。
- 问：哪一步让你**最放心/最不放心**？如果只能保留一个功能，保留哪个？

### 收尾
- 整体看，你**最希望被解决的一个问题**是什么？
- 你身边还有谁应该我们来聊聊？（推荐招募）

## 六、追问技巧 & 反引导清单

**多用**："举个例子""上一次是啥时候""然后呢""为什么"
**少问/避免**：
- ✗ "你觉得我们的产品好吗？"（诱导）
- ✗ "你需不需要可改的 SQL？"（封闭+引导）→ 改问 D1/D3 行为型问题
- ✗ 连续是/否问题
**当对方说"挺好的"**：追问"好在哪、能具体说一次使用场景吗"
**当对方沉默**：给具体情境，"比如老板突然问你一个数字，你此刻会怎么做"

## 八、访谈后分析框架（Synthesis）

1. **逐条结算假设**：汇总所有受访者对 H1–H6 的标记，统计 验证/推翻/需补充 比例，输出结论。
2. **Affinity 聚类**：把所有"关键引用"贴墙，按主题聚类，提炼 3–5 条核心洞察。
3. **优先级矩阵**：把 G1 排序结果汇总成"必备度 × 差异化度"二维图，对齐拆解表 P0/P1/P2。
4. **反直觉发现**：专门记录"和我们假设相反"的内容（最有价值）。
5. **输出物**：《访谈洞察报告》→ 直接喂给 PRD 功能清单与 MVP 范围决策。
